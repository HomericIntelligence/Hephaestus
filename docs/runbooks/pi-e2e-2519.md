## Verification Criteria

- `fixture` validates the deterministic fixture contract.
- `workflow` requires inventory, command, and repository snapshot evidence.
- `capture` requires each Pi stage's own host-observed provider invocation, exact policy scopes, and session binding when stateful.
- `comparison` requires a persisted Pi/control pair for the same fixture, stage, prompt, revision, outcomes, and artifact digests.
- `mnemosyne` requires persisted Pi-bound Athena advise and learn receipts, including LearnDeliveryReceipt PR readback evidence.
- `publication` requires deterministic manifest-to-document rendering.
- `completion` requires every stage receipt, isolated worktree/revision evidence, fixture test result, commit/PR/review/handoff readbacks, and all criteria above.
