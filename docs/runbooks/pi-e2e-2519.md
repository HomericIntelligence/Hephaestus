# Pi Issue 2519 Runbook

This runbook reproduces the live Pi/Codex conformance evidence for issue
#2519. The private raw artifacts stay under `build/pi-e2e-2519/<run-id>/`; the
published report and operator runbook are rendered into the tracked `docs/`
tree.

## Target Fixture

- `fix(utils): reject negative byte sizes`
- Exercise `hephaestus/utils/helpers.py human_readable_size` and
  `tests/unit/utils/test_general_utils.py TestHumanReadableSize` with a deterministic
  non-negative-size rejection contract.

## Evidence Root

- Run directory: `build/pi-e2e-2519/<run-id>/`
- Manifest: `build/pi-e2e-2519/<run-id>/run.json`
- Report: `docs/pi-e2e-2519-report.md`

## Collection Steps

1. Initialize a fresh run directory.
2. Record the exact Pi package inventory and required skill commands.
3. Capture Pi and Codex control runs through the temporary provider proxy.
4. Record a failure probe for any intentionally broken stage boundary.
5. Record each defect as a follow-up issue.
6. Render the report and runbook from the private manifest.
7. Attest publication readiness against the rendered docs.

## Direct Commands

```bash
uv run python scripts/pi_e2e_2519.py init --run-id <run-id>
uv run python scripts/pi_e2e_2519.py inventory --run-id <run-id>
uv run python scripts/pi_e2e_2519.py snapshot --run-id <run-id> --label repo-snapshot
uv run python scripts/pi_e2e_2519.py capture --run-id <run-id> --stage planning --provider pi -- <command...>
uv run python scripts/pi_e2e_2519.py failure-probe --run-id <run-id> --stage review --provider codex -- <command...>
uv run python scripts/pi_e2e_2519.py record-defect --run-id <run-id> --summary "<summary>" --follow-up-issue <issue>
uv run python scripts/pi_e2e_2519.py render --run-id <run-id>
uv run python scripts/pi_e2e_2519.py verify --run-id <run-id> --criterion publication --report docs/pi-e2e-2519-report.md --runbook docs/runbooks/pi-e2e-2519.md
uv run python scripts/pi_e2e_2519.py attest-publication --run-id <run-id> --repo HomericIntelligence/Hephaestus --ref main --verify-defects
```

## Verification Criteria

- `fixture` validates the fixed issue fixture title/body pair.
- `workflow` validates that inventory, snapshots, and command records exist.
- `capture` validates that provider JSON events produced session IDs and tool
  scopes.
- `comparison` validates that at least two provider runs were collected.
- `mnemosyne` validates that the required Athena skill commands were observed.
- `publication` validates that the rendered report and runbook exist and match
  the manifest.
